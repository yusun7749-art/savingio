# SAVINGIO 공식 글쓰기 헌법
## Ultimate Page Writing Constitution / ABSOLUTE LOCK

최종 갱신: 2026-07-27 KST
상태: 공식 헌법 / 절대 LOCK
적용 대상: Savingio의 기존 글 재작성, 신규 글 작성, 통합, 삭제, 301 리디렉션, Factory, CMS, Admin, QA, SEO, 배포 전 검수

---

## 0. 이 문서의 지위

이 문서는 참고자료가 아니다.

이 문서는 Savingio의 모든 콘텐츠 작업에 적용되는 공식 글쓰기 헌법이다.

모든 AI, 작업자, Factory, CMS, 자동화 엔진은 이 문서보다 임의의 템플릿, 과거 관행, 글 수 목표, 키워드 수 목표를 우선할 수 없다.

추가 지시가 없는 한 이 헌법 외의 요소를 임의로 추가·삭제·이동·축소·변경하지 않는다.

---

## 1. Savingio의 존재 이유

Savingio는 글을 늘어놓는 블로그가 아니다.

Savingio는 사용자가 생활 문제를 한 페이지에서 해결하도록 돕는 문제 해결 플랫폼이다.

모든 콘텐츠는 다음 질문을 통과해야 한다.

> 이 페이지 하나만으로 사용자가 같은 주제를 다시 검색하지 않아도 되는가?

YES일 때만 완료다.

NO라면 미완성이다.

---

## 2. 글 개수는 목표가 아니다

Savingio는 200개, 100개, 50개, 10개의 글을 유지하는 것을 목표로 하지 않는다.

필요하다면 대표글이 단 1개만 남아도 된다.

단, 그 1개는 사용자가 실제로 필요한 정보와 다음 행동까지 모두 해결하는 초고품질 Ultimate Page여야 한다.

대표글 수는 사전에 정하지 않는다.

새로운 검색 의도가 실제로 확인될 때만 새 대표글을 만든다.

---

## 3. One Search, One Answer 원칙

하나의 검색 의도는 하나의 Ultimate Page에서 끝낸다.

같은 검색 의도를 여러 URL과 여러 글로 쪼개지 않는다.

다음은 새 글 생성 사유가 아니다.

- 키워드가 조금 다름
- 제목을 다르게 만들 수 있음
- 검색량이 있음
- 카테고리를 채우고 싶음
- 글 개수를 유지하고 싶음
- 광고 노출 페이지를 늘리고 싶음

검색 의도가 본질적으로 다를 때만 별도 대표글을 만든다.

---

## 4. 제목이 아니라 검색 의도로 통합한다

통합 여부를 제목만 보고 판단하지 않는다.

반드시 본문과 사용자 목적을 확인한다.

다음 질문으로 판단한다.

- 사용자는 왜 이 내용을 검색했는가?
- 해결하려는 실제 사건은 무엇인가?
- 결정하려는 것은 무엇인가?
- 신청, 비교, 계산, 환급, 사고 처리 등 행동 목적이 같은가?
- 두 글을 따로 읽어야 할 이유가 실제로 있는가?

같은 문제를 해결한다면 하나의 대표글로 통합한다.

---

## 5. 대표글은 수정하지 않고 새로 창조한다

기존 대표글을 부분 수정하거나 문단을 덧붙여 완성하지 않는다.

기존 대표글과 관련 글은 참고 자료일 뿐이다.

보존 대상은 다음뿐이다.

- 유지하기로 결정한 URL
- 파일명
- slug
- canonical
- H1과 핵심 검색 의도
- 카테고리
- 검증된 사실, 공식 출처, 실제 필요한 정보

기존 문장, AI 표현, 문단 구조, 반복 설명은 재사용하지 않는다.

최종 대표글은 빈 문서에서 처음부터 새로 작성한다.

---

## 6. 관련 글 전수 조사 후 작성한다

대표글을 작성하기 전에 같은 검색 의도와 인접 질문을 가진 Savingio 내부 글을 모두 조사한다.

조사 대상은 제목 검색으로 끝내지 않는다.

- 본문 내용
- 사용자가 해결하려는 문제
- 표와 계산
- 사례
- FAQ
- 공식기관 링크
- 예외 조건
- 오래된 정책과 최신 정책
- 중복 URL
- 잘못 연결된 내부 링크

유용한 정보는 대표글 설계에 흡수하되 기존 문장은 복사하지 않는다.

---

## 7. Knowledge Map 선행 원칙

목차부터 만들지 않는다.

본문 작성 전에 해당 주제에서 사용자가 실제로 궁금해할 질문을 최대한 수집한다.

질문 지도에는 최소한 다음 영역을 검토한다.

- 지금 무엇을 해야 하는가
- 누가 대상인가
- 조건과 제외 조건은 무엇인가
- 얼마가 드는가 또는 얼마나 절약되는가
- 신청·가입·해지·환급 절차는 무엇인가
- 필요한 서류는 무엇인가
- 언제 해야 하는가
- 놓치기 쉬운 예외는 무엇인가
- 자주 하는 실수는 무엇인가
- 실제 사례에서 결과가 어떻게 달라지는가
- 계산이 필요한가
- 공식기관 어디에서 확인하는가
- 문제가 해결되지 않을 때 다음 단계는 무엇인가

목차는 Knowledge Map을 모두 정리한 뒤 만든다.

---

## 8. 분량이 아니라 정보 완결성이 기준이다

5,000자는 최소 품질선일 수 있으나 완료 기준이 아니다.

10,000자, 15,000자, 20,000자 이상도 필요하면 작성한다.

반복 문장과 불필요한 서론으로 분량을 채우지 않는다.

필요한 정보가 6,000자에 완결되면 억지로 늘리지 않는다.

필요한 정보가 20,000자여야 해결되면 줄이지 않는다.

완료 기준은 오직 다음이다.

> 사용자가 같은 문제를 해결하기 위해 다시 검색할 질문이 남아 있는가?

---

## 9. 공식 사실 검증 의무

정책, 법률, 보험, 세금, 환급, 지원금, 금액, 비율, 일정, 자격 조건은 기억이나 기존 글만으로 작성하지 않는다.

반드시 현재 공식 자료를 확인한다.

- 정부 및 공공기관
- 법령 및 고시
- 보험사·금융사 공식 안내
- 지방자치단체
- 공공요금 기관
- 공식 계산 기준

확인하지 못한 수치와 조건을 단정하거나 만들어내지 않는다.

시행 시점, 대상, 예외, 지역·상품별 차이를 명확히 구분한다.

---

## 10. 고정 글 DNA

각 Ultimate Page는 주제 특성에 맞게 깊이를 확장하되 기본 흐름은 유지한다.

1. Breadcrumb
2. H1
3. Lead
4. 작성·검수 정보
5. 5초 결론
6. 30초 질문
7. 지금 해야 할 행동
8. 목차
9. 상세 본문
10. 비교표
11. 체크리스트 또는 내 상황 찾기
12. 실제 사례
13. 보험·제도·법률·예외 설명
14. 계산기 또는 공식기관 연결
15. FAQ
16. 문제 해결 사슬형 관련 글
17. Footer

본문 상단의 불필요한 figure 썸네일은 사용하지 않는다.

---

## 11. 레이아웃 절대 LOCK

기준 DNA 페이지의 HTML·CSS·JS·Header·Footer·Breadcrumb·반응형 구조를 임의 변경하지 않는다.

데스크톱 3분할 구조를 유지한다.

- 왼쪽: Navigation / Explorer
- 중앙: 본문
- 오른쪽: 행동 지원 카드

왼쪽 Explorer를 임의로 삭제, 축소, 자동 제목 나열 방식으로 변경하지 않는다.

중앙 본문 폭, 카드 간격, 반응형 기준을 디자인 개선이라는 이유로 자의적으로 바꾸지 않는다.

오른쪽에는 정확히 다음 5개 목적의 카드를 유지한다.

1. 지금 해야 할 행동
2. 계산기 또는 점검도구
3. 같은 카테고리 글
4. 함께 볼 관련 글
5. 다음 단계 또는 주의사항

카드 수, 목적, 순서를 임의로 줄이거나 바꾸지 않는다.

---

## 12. 표·체크리스트·사례·FAQ는 장식이 아니다

각 요소는 실제 문제 해결에 필요할 때 깊이 있게 작성한다.

- 비교표: 조건, 비용, 장단점, 선택 기준이 한눈에 보여야 한다.
- 체크리스트: 사용자가 자신의 상황을 판단하거나 바로 행동할 수 있어야 한다.
- 사례: 조건이 달라질 때 결과가 어떻게 달라지는지 보여야 한다.
- FAQ: 본문을 반복하지 말고 남아 있는 실제 질문을 해결해야 한다.
- 계산기: 입력값, 계산식, 결과 의미, 한계를 설명하고 올바른 목적지로 연결한다.
- 공식기관: 단순 링크 나열이 아니라 언제 무엇을 확인할지 안내한다.

---

## 13. 내부 링크 원칙

같은 검색 의도를 억지로 여러 페이지에 나누고 서로 이동시키지 않는다.

내부 링크는 현재 페이지에서 해결할 수 없는 별도의 검색 의도에만 연결한다.

사용자가 A 글 → B 글 → C 글을 계속 돌아다녀야 핵심 답을 얻는 구조를 금지한다.

현재 페이지의 주제는 현재 페이지 안에서 끝낸다.

---

## 14. 통합·삭제·301 원칙

Ultimate Page가 완성되고 검증된 뒤 흡수 대상 글을 처리한다.

순서는 다음과 같다.

1. 대표 URL 확정
2. 관련 글 정보 흡수
3. 대표글 완전 재작성
4. 대표글 QA
5. 흡수 대상 내부 링크 변경
6. 흡수 대상 URL 삭제
7. 흡수 대상 URL에서 대표 URL로 301 리디렉션
8. sitemap 정리
9. canonical 검증
10. Search Console 제출 준비

대표글 완성 전에 기존 URL을 먼저 삭제하지 않는다.

삭제만 하고 301을 누락하지 않는다.

---

## 15. 신규 글 생성 규칙

새 글은 다음 조건을 모두 충족할 때만 만든다.

- 기존 Ultimate Page에 넣으면 검색 의도가 흐려진다.
- 사용자의 목표 행동이 명확히 다르다.
- 독립된 답과 구조가 필요하다.
- 기존 글과 중복되지 않는다.
- 새 페이지 역시 Ultimate Page 수준으로 완성할 수 있다.

조건을 충족하지 못하면 기존 대표글을 강화한다.

---

## 16. 금지 사항

다음을 절대 금지한다.

- 기존 글 문단 이어붙이기
- 제목과 키워드만 바꾼 유사 글
- 얇은 글 유지
- 글 개수 확보용 신규 작성
- 광고 노출용 페이지 분할
- 같은 설명의 반복
- 확인하지 않은 정책·수치 단정
- AI 특유의 공허한 서론과 결론
- 관련 링크만 늘어놓고 본문에서 답하지 않는 구조
- 5,000자 도달만으로 완료 처리
- Production 확인 없이 PASS 선언

- 비교표 포함

## 18. 애드센스 저가치 콘텐츠 대응 원칙

애드센스 재승인을 위해 글 개수를 늘리지 않는다.

우선순위는 다음과 같다.

1. 중복 검색 의도 제거
2. 얇은 글을 Ultimate Page로 흡수
3. 대표글 완전 재작성
4. 오래되거나 부정확한 정보 수정
5. 불필요한 URL 삭제 및 301
6. 내부 링크와 sitemap 정리
7. 사이트 전체 QA
8. 재심사 신청

애드센스 승인은 목표이지만, 승인만을 위한 공허한 글은 만들지 않는다.

---

## 19. 최상위 완료 문장

모든 작업자는 최종 검수에서 반드시 다음 질문에 답한다.

> 이 페이지를 읽은 사용자가 같은 문제로 다른 사이트를 다시 검색할 이유가 남아 있는가?

남아 있다면 미완성이다.

남아 있지 않고 사실·구조·기술·배포 검증까지 끝났을 때만 PASS다.
