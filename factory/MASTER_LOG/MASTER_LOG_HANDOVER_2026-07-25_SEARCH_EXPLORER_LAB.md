## 2. 검색·정보센터 성능 개선

### 기존 문제

- `articles/index.html`에 약 200개 이상의 카드 HTML이 모두 포함되어 있었다.
- 브라우저가 보이지 않는 카드까지 전부 파싱하고 DOM에 올렸다.
- 검색 시 전체 카드가 이미 DOM에 존재해 초기 로딩과 페이지 이동이 느렸다.
- 검색 결과는 12개만 보이지만 실제로는 모든 카드가 메모리에 존재했다.

### 적용한 방향

- `articles/index.html`의 정적 카드 묶음을 제거했다.
- 빈 목록 컨테이너를 먼저 로드한다.
- Registry 데이터를 기반으로 현재 페이지의 12개 카드만 동적으로 생성한다.
- 페이지 이동 시 기존 12개를 제거하고 다음 12개만 생성한다.
- 검색 입력은 debounce 처리한다.
- Explorer의 글 목록도 카테고리를 펼칠 때만 생성한다.

### 주요 수정 파일

## 4. 전체 페이지 배경 통일 문제

### 사용자가 요구한 기준

페이지별로 각자 다른 배경을 만드는 방식은 금지한다.

메인 페이지와 동일한 공통 배경 DNA를 전체 공개 페이지에서 공유해야 한다.

공통 요소:

- 크림 톤 배경
- 메인과 동일 계열의 기하학 원형
- 사선형 빛 무늬
- 골드 점무늬 또는 메인 기하 장식
- 페이지 본문·카드만 그 위에 올라가도록 구성

### 발생한 문제

- 정보센터, About, Lab, 일반 글, 계산기 페이지마다 배경 색과 무늬가 달랐다.
- 계산기에는 푸른 회색 계열 배경이 남아 있었다.
- 일부 페이지에는 메인의 기하학 무늬가 보이지 않았다.
- 페이지별 CSS 수정으로 인해 일관성이 다시 깨졌다.

### 적용한 수정

- `css/style.css`에 공통 배경 잠금 추가
- 계산기 전용 배경값 제거
- 계산기 `body::before` 전용 배경 제거 후 공통 배경 사용
- 페이지 shell과 main 영역을 투명 처리
- 공통 크림 배경을 `html`, `body` 기준으로 고정

따라서 배경 통일은 최종 완료가 아니다.

## 6. Explorer 분류 오류

### 가장 큰 문제

기존 Explorer에서 `금융 204개`가 표시됐고, 전기요금·수도요금·건조기·정부지원·여행·연금·사업 관련 글까지 금융에 들어갔다.

하단 카테고리는 0, 1, 2, 3, 5개처럼 비정상적으로 작았다.

### 사용자의 핵심 지적

- 돈이 들어간다고 금융이 아니다.
- 검색은 전체 글에서 되더라도 분류는 정확해야 한다.
- 사업자 비용, 폐업, 소상공인 배달비는 금융이 아니다.
- 국민연금, 노령연금, 기초연금은 연금·노후다.
- 휴가철 렌터카는 자동차·교통 또는 여행 맥락이다.
- 여름 휴가 예산은 여행·여가다.
- 저소득 냉방비 지원은 정부혜택이다.
- 누수, 전월세, 반환보증은 주거다.

### 분류 철학 LOCK

검색은 전체 대상으로 한다.

분류는 **돈 여부가 아니라 주제 기준**으로 한다.

금융은 다음처럼 금융상품·금융기관 중심으로 제한한다.

- 은행
- 카드
- 대출
- 계좌
- 예금
- 적금
- 신용
- 금융상품으로서의 보험

다음은 금융이 아니다.

- 생활비
- 전기·수도·가스·관리비
- 정부지원
- 세금
- 사업자 비용
- 폐업
- 연금
- 여행 예산
- 렌터카
- 누수
- 주거

### 추가한 카테고리 방향

- 금융
- 생활비 절약
- 정부혜택
- 세금·환급
- 직장·급여
- 자동차·교통
- 연금·노후
- 아이·교육
- 주거
- 생활정보
- 사업·자영업
- 여행·여가
- 건강·의료

### 적용한 기술 수정

- 기존 `item.category`를 무조건 신뢰하는 방식 제거
- 제목, 설명, 검색 키워드, exact query를 함께 분석
- 제목 우선 가중치 적용
- 카테고리별 키워드 점수 계산
- 단순히 `비용`, `금액`, `돈` 같은 표현 때문에 금융으로 보내지 않도록 수정

### 수정 파일

- `data/savingio-category-tree.json`

- `js/savingio-brain-navigation.js`

코드는 개선됐지만 Explorer의 최종 분류는 아직 사용자 승인 전이다.

- 분류와 검색을 완전히 분리한다.

## 11. 운영 주의사항

- 사용자가 이미지 생성 요청을 하지 않았는데 이미지 생성 도구를 사용하지 않는다.
- 사용자가 실제 파일 수정이나 삭제를 요청하면 GitHub 도구를 먼저 확인하고 직접 실행한다.
- GitHub 쓰기 권한이 없다고 추측하지 않는다.
- 브라우저 화면을 확인하지 못했으면 `GitHub 반영 완료 / 운영 화면 미확인`으로 정확히 보고한다.
- 페이지 하나를 고칠 때 다른 페이지의 디자인이나 글씨 크기를 임의로 바꾸지 않는다.
- 공통 영역 변경은 반드시 전체 페이지 회귀 영향까지 고려한다.
